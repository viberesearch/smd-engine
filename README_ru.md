# smd-engine

[English version: README.md](https://github.com/viberesearch/smd-engine/blob/main/README.md)

`smd` - консольная программа для мыследеятельностных сессий в традиции СМД (системомыследеятельностная методология, школа Г. П. Щедровицкого). Она делает пять вещей:

1. Хранит состояние сессии как запись YAML: доски, позиции, рамки, функции, разрывы, квалификации, пронумерованные переходы, тезисы из стенограммы, гипотезы, подписи человека.
2. Проверяет запись по схеме, по соглашениям методологии и, между циклами, по предыдущему циклу.
3. Рисует запись как SVG-экран, пошаговые кадры, граф в 3D, указатель со строками YAML, Markdown, Mermaid или хранилище Obsidian. Рисунки порождаются, руками их не правят.
4. Применяет решения как записи: правка текущего цикла или следующий цикл с подписями человека.
5. Собирает процедуру мышления, роли и линзы в один файл Markdown, который выполнит любая модель, и сравнивает результат прогона с эталонной записью.

Экран по умолчанию - экран из трёх досок† программы МФТИ «Третья ступень»: оргдеятельностная, объектная и ситуационная†. Профиль может задать другие доски: `classic-two-boards` - классическая пара оргдеятельностной и объектно-онтологической досок. Какие слова принадлежат программе, а какие классике, сказано в `roles/README.md`.

† - термин программы «Третья ступень», не классической методологии (список ниже, в разделе «Слова программы»).

Версия 0.3.6, схема 0.3. Python 3.14. Программа предлагает и проверяет; решает человек, подписями, у каждой из которых названа функция.

## Установка

Без установки, из репозитория:

```bash
uvx --from git+https://github.com/viberesearch/smd-engine smd validate путь/к/кейсу
```

Или из PyPI:

```bash
pip install smd-engine
smd --help
```

Из рабочей копии, для разработки (только `uv`):

```bash
uv sync
uv run smd --help
```

В пакет входят процедуры, роли, линзы, профили и модель данных, поэтому `smd pack` работает и из установленной копии.

## Попробовать

В репозитории два выдуманных учебных кейса с одним содержанием: `cases/example` (подписи по-английски) и `cases/example_ru` (подписи по-русски). Три пекарни думают об общем производстве для независимых пекарен региона.

```bash
uv run smd validate cases/example_ru --sources cases/example_ru/sources.yaml --hints
uv run smd render cases/example_ru/pekarni-c2.board.yaml -o out/screen.svg
uv run smd frames cases/example_ru/pekarni-c2.board.yaml -o out/frames.html
```

## Команды

Примеры с параметрами - в `docs/commands.md` (на английском); `smd <команда> --help` перечисляет параметры.

| Команда | Что делает |
|---|---|
| `validate` | Схема, ошибки, предупреждения и (с `--hints`) методологические подсказки для записей или папок; код 1 при ошибках |
| `migrate` | Переводит записи со схемы 0.2 на 0.3; по умолчанию только сообщает, `--write` правит изменённые строки на месте |
| `render` | Одна запись как SVG, HTML, Markdown, Mermaid или текст SessionFlow |
| `frames` | Пошаговые кадры на одной HTML-странице, в порядке чтения или по циклам, с текстом к каждому кадру |
| `graph` | Доски как плоскости в 3D, записи сверху, источники снизу; одна самодостаточная страница |
| `index` | Каждая K, тезис, гипотеза, O, подпись и элемент со своей строкой YAML и ссылкой на источник |
| `publish` | Проверяет, затем пишет кадры, кадры по циклам, указатель, граф и страницу одним комплектом |
| `vault` | Хранилище Obsidian: заметка на элемент, тезис, гипотезу, K и источник |
| `sources` | Перечисляет манифест источников, проверяет файлы и sha256, делит источники для чистой комнаты |
| `compare` | Сопоставляет элементы двух записей: согласие, уточнение, конфликт; `--merge` набрасывает цикл слияния |
| `eval` | Сравнивает прогон процедуры с ожидаемой записью; код 1 ниже порогов |
| `revise` | Открывает следующий цикл записи и применяет подписи человека |
| `apply` | Применяет правку (add, set и remove по id или по номеру перехода `n`, `board_notes`, state) к записи как её следующую подверсию и проверяет результат |
| `pack` | Один файл Markdown с процедурой, её ролями, линзами, моделью данных, ячейками для заполнения и записями, для любой модели |

## Модель данных на одном экране

Полный формат - в `docs/data-model.md` (на английском). Записи - YAML; схемы JSON Schema лежат в `src/smd_engine/schemas/`.

| Запись | Что это |
|---|---|
| `board_set` | Один цикл экрана. Верхний уровень: `id`, `case`, `cycle`, `revises`, `status`, `sources`, `profile`, `run`, `applied`, `state` |
| `source_manifest` | Первичные материалы кейса: перечислены, не скопированы. `id`, `kind`, `origin`, `file` или `url`, `sha256`, `lineage`, `clean_room` |
| `taxonomies` | Значения, которые могут принимать `tags` и привязанные столбцы `detail` |
| `board_patch` | Решение по текущему циклу: `add`, `set`, `remove`, `state` |

Внутри `board_set`:

| Часть | Содержание |
|---|---|
| `elements` | `id`, `board`, `kind`, `label`; необязательно `seen_from` (позиция, с которой это видно), `in`, `performed_by`, `fillers`, `detail`, `cites`, `voice`, `epistemic`, `move`, `lens` |
| `relations`, `transitions` | Связи между элементами; пронумерованные переходы между досками |
| `qualifications` | `K1..Kn`: замечания методолога, `open`, `partly` или `closed` (квалификации† по критериям программы) |
| `theses` | Карточки из стенограммы: `claim`, `voice`, `status`, `belt` (пояс), `kind`, `feeds`, `cites` |
| `hypotheses`, `ontology` | Полевые проверки с результатом; онтологические картины, годные для названных позиций, с проверкой реализуемости |
| `signoffs` | Решения человека, у каждого функция: `close_k`, `accept_move`, `accept_thesis`, `accept_result`, `verify_record` и другие |
| `state` | Строка состояния после цикла: `version`, `difficulty`, `accepted`, `open`, `next_move` |

Что проверяет валидатор: на доске ничего не лежит без позиции, с которой это видно; голос ИИ никогда не подписывает; вариант от ИИ остаётся вариантом, пока подпись человека его не поднимет; закрытая K, уточнённый тезис и подтверждённый результат требуют подписи. Адрес в `cites` указывает в источник по идентификатору и времени, странице, реплике или строке: `s3#t=00:08:10`.

## Профили

Профиль (`profiles/*.yaml`) задаёт доски, виды элементов, виды связей, действующие подсказки и шаги чтения для `smd frames`. Запись называет свой профиль в `profile`; без него действует `program-three-boards`. Формат профиля и раскладка досок по их областям описаны в `docs/profiles.md` (на английском).

| Профиль | Доски |
|---|---|
| `program-three-boards` (по умолчанию) | оргдеятельностная `od`, объектная `oo`, ситуационная† `s` с малой† и большой† половинами |
| `classic-two-boards` | оргдеятельностная `od` и объектно-онтологическая `oo` рядом; ситуационной доски нет |
| `management-four-boards` | схема ОРУ Г.П. Щедровицкого: оргдеятельностная `od` и верхняя система ОРУ `ot` сверху, аппарат руководства `ap` и управляемая полисистема `us` снизу |

Неизвестный профиль, доска или вид элемента - ошибка с именем элемента. Формат и ключи профиля: `docs/data-model.md`, раздел Profiles.

## Как кейс использует движок

Настоящий кейс живёт в репозитории своего объекта мышления; здесь только выдуманные примеры. В репозитории кейса лежат:
- записи досок, по файлу на цикл (`<кейс>-c1.board.yaml`, `-c2`, ...), и правки (`*.patch.yaml`);
- один манифест `sources.yaml`: идентификаторы, контрольные суммы и решение «чистой комнаты» для каждого источника. Сами материалы остаются где лежали, записи ссылаются на них по идентификатору;
- при необходимости `taxonomies.yaml`.

Движок запускается без локальной копии, с закреплённой версией, например в CI:

```bash
uvx --from git+https://github.com/viberesearch/smd-engine@v0.3.6 smd validate . --sources sources.yaml --strict
```

Порождённые рисунки (`smd publish`) - результат сборки, их не коммитят. Записи старой схемы переводят командой `smd migrate`.

## Выполнить процедуру любой моделью

Процедура (`procedures/*.md`) - промпт, не привязанный к модели. Роли и линзы, которые она использует, и модель данных упаковываются вместе с ней:

```bash
smd pack small-situation cases/example/bakeries-c1.board.yaml --sources cases/example/sources.yaml -o pack.md
```

1. Приложите `pack.md` и файлы источников, которые называет процедура, к любой модели и скажите «выполни эту процедуру».
2. Модель вернёт запись. Она предлагает, но не подписывает. Решения, которые она принять не может, уходят в `state.open`.
3. Сохраните запись и запустите на ней `smd validate`. Исправьте то, о чём он сообщит.
4. Для эталонного прогона `smd eval run.board.yaml expected.board.yaml --min-agreement N` показывает, не стало ли хуже (`cases/example/golden/README.md`).
5. Решения человека запишите подписями или правкой (`smd apply`), следующий цикл откройте командой `smd revise`.

В Claude Code внутри этого репозитория `/procedure <id> <входы>` выполняет процедуру напрямую; подагенты ролей лежат в `.claude/agents/`. Процедуры перечислены в `procedures/README.md`, линзы - в `lenses/README.md` (оба на английском).

## Слова программы

Эти слова взяты из программы «Третья ступень» (материалы Гиренко, день 4), а не из классической методологии. В файлах репозитория они помечены как слова программы.

| Слово | Где встречается |
|---|---|
| ситуационная доска, малая и большая ситуация | доска `s` профиля `program-three-boards`, половины `small` и `big` |
| визионер, тракт | роль `roles/visionary.md`, процедура `visionary-tract` |
| граница нормальности, выплески | виды элементов `normality_boundary`, `signal` |
| серия связанных событий | вид `garland`; по-русски пишем «серия связанных событий» |
| квалификации (K) | `qualifications`, процедура `qualification-pass` |
| такт, станция | в тексте процедур и ролей |

Названия ролей игротехник и методолог - классические (ПГ-ГТ, ГП1983).

## Что где лежит

| Путь | Что |
|---|---|
| `src/smd_engine/` | пакет: схемы, валидатор с реестром проверок, отрисовщики, загрузчик профилей, `apply`, `migrate`, `eval`, `pack` |
| `profiles/`, `procedures/`, `roles/`, `lenses/` | файлы методологии как данные; входят в wheel под `smd_engine/assets/` |

| `CONTRIBUTING.md`, `CHANGELOG.md` | как менять движок; что добавил каждый выпуск (на английском) |
